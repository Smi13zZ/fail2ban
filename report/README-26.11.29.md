# Fail2ban 26.11.29 交付说明

Jail 管理页顶部收成一行，顺带修掉一个「按钮掉到容器外」的模板缺陷并加了闸门。

## 一、按需求逐条对照

| # | 要求 | 落地情况 |
| --- | --- | --- |
| 1 | Jail 管理页上面也做成一行 | 搜索、作用域、条数、新建 Jail 四个控件合并到同一行；13 个桌面宽度实测均一行 |

## 二、原先为什么是两行

第一行只有一个「新建 Jail」按钮，右侧全空；第二行是搜索框、作用域下拉与条数。
两行各自都只用了一半宽度，中间的空白什么也没有。

## 三、合成后

    搜索名称 / 过滤器 / 日志路径 | 已启用 | 共 N 项 | ...... | + 新建 Jail

- 搜索框可收窄：240px → 120px，内容按省略号收尾；
- 作用域下拉与条数按内容宽度，不参与压缩（条数是「筛选出几条」的唯一提示）；
- 中间用弹性空隙把「新建 Jail」推到最右。

## 四、踩到的缺陷：译文自带的 `</div>`

第一版改完，「新建 Jail」仍然掉在下面一行。查下来不是 CSS：

条数用的是 `common.countInline` 词条，而它的译文本身带一个闭合标签：

    "common.countInline": "<span class=\"hint\">共 {n} 项</span></div>"

那个结尾的 `</div>` 是给「整块内容 + 闭合容器」的场景准备的。塞进一条正在拼装的
工具栏里，容器被提前闭合，后面的弹性空隙与按钮全部掉到容器外面。
**界面看起来只是「按钮跑到了下一行」，完全看不出是模板拼错了。**

诊断过程值得记：探针显示工具栏只有 3 个子元素（应为 5），
按钮的父元素是 `<main>` 而不是工具栏 —— 一眼就能看出是多了一个闭合标签，
而不是走 CSS 排查。

改法是换用不带闭合标签的 `common.count`，外面自己包 `<span>`。

## 五、新增闸门

`tools/check_web.py` 新增 `check_block_close_suffix()`：扫描 `app.js` 里
`t('key')` 的实参 key，若该 key 的译文含 `</div>`，且调用处同一行里还在继续
拼接行内闭合标签，判 FAIL。

用变异样本验证：把 `common.count` 改回 `common.countInline`，立刻报

    FAIL app.js:1101: 'common.countInline' 的译文以 </div> 结尾，却当成行内片段接在容器里

**这道闸门第一版假绿**：它固定读仓库里那份 app.js，不认命令行传入的副本路径，
所以变异测试对着仓库文件跑，永远是 PASS。已改成接受 `app_js` 参数。
现在 46 个带 `</div>` 的词条全部核对过，没有一个被行内拼接。
