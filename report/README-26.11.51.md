# Fail2ban 26.11.51 交付说明

通知新增「面板新版本」事件、全局新版本提示、一键更新全面对齐、通知页按钮同行。

## 一、通知里能推「面板新版本」

原先只有四类事件（封禁 / 解封 / 服务异常 / 服务恢复）。面板自己出了新版本，
用户在手机上收不到任何信号。

新增第五类 `update`（界面叫「面板新版本」），后端版本自检线程发现新版本时
走同一条 `notify.dispatch` 推送：

- 与其它事件共用渠道、**事件开关**与投递记录；
- 文案中英双语：标题 `Fail2ban 面板有新版本 / Fail2ban panel update available`，
  正文中文段 + 空行 + 英文段，带当前版本与最新版本；
- **同一个版本只推一次**：`poll_loop` 内部记着已通告的版本号，长驻进程不会每小时重复。

实测 `/api/notifications` 返回的 eventTypes 已含 `update`，默认开启。

## 二、全局新版本提示

原先只有侧栏「设置」一个小红点，进设置后还要自己找「更新」标签 ——
**在一级页面上根本看不出有新版本**。

| 位置 | 状态 |
| --- | --- |
| 侧栏「设置」红点 | 保留（已有） |
| 设置页「更新」标签红点 | **新增**，与上一处同源 |
| 全页提示条 | **新增**，顶栏之下、内容之上，每个页面都在 |

提示条结构：图标 + 「检测到新版本 X（当前 Y）」+ 副标题 + 查看详情 / 一键更新 / ×。

- **查看详情** → 跳到设置 → 更新看发布说明；
- **一键更新** → 直接开升级流程；
- **×** → 本次不再出现（下次打开面板若仍有新版本还会提醒）。

手机上同一套排法收窄：标题占第一行、一键更新独占第二行、关闭按钮贴第一行右端。
实测 1440 宽度下横幅 65px 高、390 宽度下 102px 高，与内容左右边距对齐。

## 三、一键更新全面对齐

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 进度条配色 | `--accent-bar` 蓝色 | `--primary` 深色（rgb(28,28,28)） |
| 遮罩透明度 | `.55` | `.5`（rgba(0,0,0,0.5)） |
| 安装阶段文案 | 正在安装新版本 | 安装包已就绪，正在重启服务… |
| 轮询间隔 | 1000ms | 400ms |
| 确认框 | 将下载并安装 {version}… | 将下载 v{version} 并重启面板完成升级… |
| 完成文案 | 升级完成，页面即将重新加载 | 已更新到 v{v}，正在刷新… |
| 遮罩底部提示 | 升级期间请勿关闭页面。 | 完成后页面会自动刷新，请不要关闭。 |
| 超时提示 | 等待超时：面板没有在预期时间内恢复… | 等待超时，请到飞牛应用中心确认安装状态。 |
| 失败原因 | 只闪一次 toast | 同时留一行红字在更新页上 |

其余本来就一致：遮罩固定宽度与最小高度（实测两阶段都是 227px，切换不跳）、
进度区两种形态共用固定高度、百分比只增不减、下载满格后在安装阶段保留、
轮询容忍 180 次再判超时、装完自动重载。

## 四、手机端通知页的保存按钮

「保存设置」原先掉在「总开关」标题下面单独占一行。改用 `.ch-inline` 卡片头：
标题吃剩余宽度、按钮固定宽度留在右侧，与「通知渠道」「投递记录」两张卡一致。

实测 390×844：卡片头 32px（原 72px），标题与按钮同行。
