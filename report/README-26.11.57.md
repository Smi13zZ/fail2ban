# Fail2ban 26.11.57 交付说明

存储页两处修正：安装包缓存一直是空的、手机端表格要左右划。

## 一、安装包缓存为什么是空的

两个原因叠在一起。

### 1. 扫的根本不是安装包所在的目录

一键升级把包下到 **@apphome** 下的工作区，不是 @appdata。这是刻意的：升级流程是
「卸载 → 安装」，而卸载会清空 @appdata —— 包放在那里会被自己卸掉一半，回滚包也跟着
没了。而存储页只看 @appdata/update，那个目录从来没有过东西，所以永远列不出来。

### 2. 推导 @apphome 的代码其实没生效

它做的是「把 var_dir 里的 @appdata 字面替换成 @apphome」，但设备上 var_dir 是
`/var/apps/fn-fail2ban/var` —— 一个指向 `/vol1/@appdata/fn-fail2ban` 的软链接，
字面里根本没有 @appdata，替换于是原样返回，工作区仍然算在 @appdata 里。

现在先 `realpath` 再替换，两种写法都能落到 @apphome；实在认不出结构（非常规部署、
本地单测传临时目录）才退回 `<var>/update`。

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 列表数据源 | 只扫 @appdata/update | @apphome 工作区 + @appdata/update |
| 「更新缓存」占用行 | 恒为 0 | 指向真实目录，计入合计 |
| 清理 | 只删 @appdata/update | 两个目录都扫，按名字去重 |
| 保留规则 | 最新 2 个 + 运行版本 + rollback.fpk | 不变 |
| 空态 | 一句「没有缓存的安装包」 | 补一句包会落在哪个目录 |

「升级安装日志」原来标着「已计入上级目录」（nested）—— 它确实在 @appdata/update 里，
但「更新缓存」那一行现在指 @apphome 了，两者不再是同一棵树，标 nested 会让它
一分钱都不算进合计。已改成不嵌套。

## 二、存储页手机端不再左右划

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 路径列 | 占掉一半宽度，只剩「/vol1/@appda…」 | 整列收起，路径挪到项目名下面一行小字 |
| 表格布局 | auto（按内容分配宽度） | fixed（按列的定宽分配） |
| 名称 / 大小 | 加起来比视口宽 | 340px 视口内正好放下，无横向滚动 |
| 安装包表 | 同样溢出 | 同样两列就地排开 |

真正的根因是**布局模式被压回了 auto**：样式表上方有一条
`.table-wrap table:not(.fixed) { table-layout: auto }`（特异性 0,2,1），
而新写的 `.ttable.tstorage`（0,2,0）压不过它 —— 列宽又按内容算，表格比视口宽一截，
横向滑动就回来了。选择器补成 `.table-wrap table.ttable.tstorage`（0,3,1）才生效。

## 三、顺带修的一处

桌面端存储明细被切成半行：滚动盒上限写的是 330px，而表头 36 + 行 46 = 82 一格，
330 除不尽，最后一行总是半截。现在按整行算成 312px（36 + 6×46），并且只在视口
**低于 700px** 时才启用 —— 正常桌面让它整块摊开，整页本来就能滚，不必再套一层内滚动。

## 四、实测（真机 fnos-test）

先往缓存目录放了 4 个包（3 个完整 + 1 个截断的 .part）验证列表，再验证清理：

| 项 | 结果 |
| --- | --- |
| 列表 | 4 个全部列出，大小与 partial 标记正确 |
| 清理（保留 2 个） | 7 个 → 3 个：最新 2 个 + 运行版本（26.11.56） |
| 回滚包 | rollback.fpk 豁免，不占保留名额 |
| 手机 390 | 两张表都 340px 宽，`scrollWidth == clientWidth`，溢出 0 |
| 桌面 1440 | 13 行完整显示，不再有半行 |
| 空态 | 说明包落在 `/vol1/@apphome/fn-fail2ban/update` |
