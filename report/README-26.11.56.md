# Fail2ban 26.11.56 交付说明

通知分区的渠道列表与投递记录重做，并修好「点测试后记录不出来」。

## 一、点测试后投递记录不出现

这是本次唯一的**功能性**问题，界面好不好看是次要的。

测试按钮发完消息只弹一个 toast，从不重读记录。列表里那份数据是进页面时取的一次
快照，所以点完之后看到的仍然是点之前的内容；要看到刚发的那条，只能手动点「刷新」
或退出重进通知分区。记录其实一直写进去了，问题只在前端读不到。

| 时机 | 现在的行为 |
| --- | --- |
| 测试成功 / 失败 | 都重取一次记录（失败也会留一条带原因的记录） |
| 发送期间 | 按钮显示「发送中…」并禁用 —— 上游超时要等几秒，按钮没反应会让人连点 |
| 刷新 / 切筛选 / 清空 | 走同一套取数，取完立即重绘 |

顺带修了两处同源问题：

1. 设置页任何一次重绘都会换掉整块 DOM，投递记录是「只露 5 条」的滚动盒，
   翻到下面再被弹回顶端很难用 → 重绘前记下滚动位置、画完放回去；切筛选时则
   有意回到顶端（列表内容整批换了，旧位置没有意义）。
2. 「通知」标签上的失败红点原本就地数当前列表里的失败条数，切到「成功」筛选时
   数出来是 0、红点自己就灭了 → 条数改由后端按全部记录统计。

## 二、通知渠道

一条渠道一行：左侧圆形铃铛 + 名称与「类型 · 状态」+ 右侧「测试 / 编辑 / 删除」。

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 名称 | 不省略，长名字把按钮挤出去 | 单行省略，按钮位置稳定 |
| 状态 | 彩色徽章 | 纯文字（徽章在 13px 的行里比名字还显眼） |
| 目标摘要 | 单独一行（密钥掩码 / 地址） | 去掉 —— 掩码读不出信息，地址又太长 |
| 空态 | 图标 + 半句 + 底部半句 | 图标 + 一整句，底部只留支持列表 |
| 手机端 | 三个动作各占一条 | 图标与名称一行，三个动作下一行左右均分 |

## 三、投递记录

一条记录一张小卡：结果药丸 → 标题 + 事件标签 → 正文（最多三行）→ 渠道与时间；
失败行在最下面再加一行原因（等宽字体、危险色）。

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 行结构 | 一个圆点 + 标题 + 事件 + 时间 | 药丸 + 标题 + 事件标签 + 三行正文 + 渠道与时间 |
| 失败原因 | 混在正文里、前缀「原因:」 | 单独一行，独立配色 |
| 可见条数 | 全部展开 | 固定露 5 条，其余在卡片内滚动 |
| 列表高度 | 无上限 | 按前 5 行**实测**高度算 |
| 滚动条 | 无样式 | 6px 常显、悬停加深 |
| 卡片头 | 标题独占一行，筛选另一行 | 标题 → 筛选 → 刷新 → 清空 同一行；窄屏只有筛选换行 |
| 失败提示 | 无 | 「失败」筛选上带失败条数徽标 |
| 英文界面 | 正文原样显示中英双语 | 只取英文段 |

**为什么高度要实测**：行高随正文行数（1–3 行）与失败原因长短变化，从 134px 到
175px 不等。写死一个 `max-height` 一定会在某一行中间切开 —— 用户看到的正是
「最后一条被裁掉半截」。现在按前 5 行的真实高度求和（含 8px 间距）再设上限。

## 四、实测

真机（`fnos-test`）量出来的几何：

| 项 | 桌面 1440 | 手机 390 |
| --- | --- | --- |
| 投递列表可见条数 | 5（第 5 行底边差 -1px） | 5（-0.1px，不切半行） |
| 列表可滚动 | 是（可滚 431px） | 是（426px） |
| 卡片头排布 | 标题 / 筛选 / 刷新 / 清空 同一行 | 标题 + 两个动作一行，筛选整行第二行 |
| 渠道行高度 | 62.5px（三个按钮同一行） | 104.5px（按钮沉到第二行） |
| 整页横向溢出 | 0 | 0 |

功能实测（真机点按钮，不是读代码）：

- 点「测试」→ 15 次采样里前 10 次按钮是「发送中…」并禁用，结束后自动恢复，
  记录条数从 9 变 10，新记录排在首位；
- 「全部 / 成功 / 失败」三种筛选行数 10 / 9 / 1，失败徽标恒为 1；
- 滚到 120px 后点「刷新」，位置保持 120；切筛选后回到顶端；
- 点「清空」弹的是站内确认框（不是浏览器原生 confirm），取消后数据不变；
- 英文界面：事件名、结果药丸、事件标签、说明段全部英文，正文只取英文段；
- 深色主题：药丸底色与文字对比正常，无残留浅色块。

## 五、后端

`/api/notifications/deliveries` 的返回增加两个字段，都不含密钥：

- `max`：环形缓冲上限（300），界面据此写「最多保留最近 300 条」；
- `fail`：全部记录里的失败条数，红点与徽标都用它。
