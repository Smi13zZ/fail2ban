## 二、行序倒过来之后必须一起处理的事

倒序本身只是把数组反一下，但它会让「自动刷新」的体验立刻坏掉：

自动刷新每 5 秒把整块列表重绘一次。原来新行追加在末尾、滚动位置停在底部，
重绘后归零到顶部对读者几乎无感；倒序之后新行顶在最上面，重绘若把 scrollTop 归零，
用户正在读的中间那几行就会整体上跳好几百像素。

所以重绘时同时记住 `scrollTop` 与 `scrollHeight`：

- 本来就停在最上面（scrollTop ≤ 4）：留在顶部跟着最新一行；
- 停在中间：新行顶进来多少，就往下让多少（`scrollTop += 高度差`），正在读的行留在原地；
- 只有切换级别筛选、改关键字才回到顶部 —— 那是一次全新的查询。

实测：滚到 900px 处等一轮自动刷新（6.5s），scrollTop 前后都是 900，
总高度 2776 不变，首行仍是 16:36:21 的最新记录。

## 三、工具栏

原先关键字、行数、导出压在页面底部的次要工具条里，刷新与自动刷新在顶部，
翻日志时视线要来回跳。现在合成一条：

    关键字过滤 | 400 行 | 导出 | 刷新 | 自动刷新

顺序的理由：越靠右越接近「重新取一次」，所以刷新与自动刷新挨在一起；
参数类的关键字与行数排在它们左边。

关键字框从 220px 放宽到 260px：英文占位符
"Filter by keyword (IP, jail name…)" 实测要 235px（文字 213 + 内边距 22），
220px 会把结尾吃掉半个词。

手机端（390 CSS px）自动分三行：级别筛选一行、关键字独占一行、
行数 / 导出 / 刷新 / 自动刷新一行；实测无横向溢出（scrollWidth == innerWidth == 390）。

## 四、勾选框

原来用的是滑块开关（一条轨道加圆点），放在这里读不出「勾选」的意思。
换成方形勾选框：

- 16px 见方、4px 圆角，与旁边 13px 的文字同高 —— 再大就会比文字高出一截，看着像按钮；
- 勾选时整块填成前景色、勾用背景色，深色与浅色主题下都清楚；
- 框和文字在同一个 `<label>` 里，点文字也能切换。
