# fn-fail2ban 26.11.6 · 设置页重做

26.11.5 把通知、存储、更新三块能力补齐之后，侧栏涨到十项，其中四项（通知设置、存储、
更新、全局设置）本质都是「配置」，却各自占了一个一级入口；全局设置自己又是一个两列平铺
的长页，按钮散落在各卡片里，和其余页面的排版不一致。这一版把这四处收进一个设置页，
页内用标签条分区，并把按钮排版统一。

## 1. 导航从十项收成七项

   概览 / Jail 管理 / 封禁管理 / 过滤器 / fnknock 联动 / 设置 / 运行日志

「通知设置」「存储」「更新」「全局设置」四个入口合并进「设置」。侧栏「更新」红点
（`#navUpdateDot`）搬到「设置」按钮上，有新版本时仍然一眼能看见。

## 2. 设置页的八个分区

| 分区 | 内容 | 数据来源 |
| --- | --- | --- |
| 面板 | 日志页默认行数、保存后自动重载、危险操作二次确认 | `/api/prefs` |
| 外观 | 主题、界面语言、侧栏布局、表格密度 | `/api/prefs` |
| 防护策略 | 默认防护策略与全局白名单（原「全局设置」整块） | `/api/settings` |
| 通知 | 主开关、事件开关、渠道列表、投递记录（原整页） | `/api/notifications` |
| 备份 | 自动备份设置与备份清单 | `/api/backup` |
| 存储 | 空间占用与三个清理入口（原整页） | `/api/storage` |
| 更新 | 版本检查、发布说明、一键升级（原整页） | `/api/update` |
| 关于 | 面板版本、托管文件、读取顺序、备份与数据目录 | `/api/meta` |

每个分区只拉自己需要的接口：进「关于」不会顺带把通知渠道读一遍，切分区是瞬时的。

## 3. 路由

- 地址栏形如 `#settings/notify`，深链可直接打开任一分区。
- 旧的 `#notifications`、`#storage`、`#update` 会自动跳到对应分区并改写地址栏，
  已保存的书签不会失效。
- 页内切分区用 `history.replaceState` 改写地址，不往历史里堆记录：点后退仍回到上一个页面，
  而不是在设置页的分区之间打转。
- 顶栏标题带上分区名（「设置 · 通知」），任何时候都知道自己在哪一块。

## 4. 外观三项新偏好（服务端保存）

| 偏好 | 取值 | 说明 |
| --- | --- | --- |
| 界面语言 | 跟随浏览器 / 中文 / English | 此前只存在浏览器本地，现在存在服务端 |
| 侧栏布局 | 记住上次状态 / 默认展开 / 默认收起 | 折叠按钮永远只改本机记忆，不改偏好 |
| 表格密度 | 舒适 / 紧凑 | 紧凑只压行高与卡片内边距，不动字号与圆角 |

后端 `store.DEFAULT_PREFS` 增加 `lang` / `sidebar` / `density` 三项，
并加了取值收敛：拼错的枚举回落默认值，`logLines` 收敛到 20–5000。
旧版 `prefs.json` 缺这些键时自然回落，不需要迁移。

## 5. 按钮排版统一

- 卡片标题行的行内动作靠右：`.card-head`（标题 + 弹性空隙 + 动作）。
- 卡片底部动作条：`.card-foot`，一条上边线把操作区与内容分开，主按钮固定在最右。
- 窄屏时底部动作条换行，主按钮独占一整行，便于单手点按。
- 设置页范围内不再有内联间距补丁（`style="margin…"` 已清零），间距一律由样式类给出。

## 6. 备份清单表格重排

原先是「表单 | 清单」左右两栏，每栏只有约 570px：文件名被截成同一个省略号，
时间列被折成两行、每行高度都不一样。现在改成上下结构——表单自己用两列网格，
清单占满整张卡片宽度，并改为固定列宽 + 时间列 nowrap：

    文件名（1fr 自动伸缩） | 大小 88px | 时间 156px | 操作 132px

## 7. 顺手修掉的三个问题

1. **切分区不拉数据导致永远「加载中…」**：`setSettingsTab` 最初只重绘不取数，
   切到没访问过的分区会停在占位文案上。改为先画占位、再拉数据、回来后只重绘仍在当前分区的情况。
2. **异步回来不重绘**：通知/存储/更新三处的 `state.view === 'notifications'` 之类的判断
   在合并进设置页后永远为假，数据回来了界面不动。改为 `inSettingsTab('notify')` 之类的判定。
3. **折叠按钮与侧栏偏好互相打架**：偏好在 `expanded` / `collapsed` 时，按钮点完
   又被 `applySidebarPref` 按偏好覆盖回来，界面上表现为「点了没反应」。
   现在按钮只写本机记忆、不回写偏好，也不需要给按钮加看不见的 `locked` 状态类。

## 9. 已知限制

- **一键升级仍受 fnOS 限制**：`appcenter-cli uninstall` 拒绝卸载第三方应用
  （「please uninstall it from Web UI」），因此升级脚本走的是文件级替换。
  真正的升级入口仍是应用中心 Web UI，这一点从 26.11.5 起没有变化。
- **版本检查默认查不到仓库**：`Smi13zZ/fail2ban` 尚未发布，设备上的默认结果是
  「找不到更新仓库」。这是预期状态，仓库发布后即恢复。
- **未改动的部分**：`cmd/*` 与 `wizard/*` 一字未动（与 1.7.0 的既有差异仍是
  「删掉登录页」相关的三处，`inspect_fpk --strict` 每次都复核）。
