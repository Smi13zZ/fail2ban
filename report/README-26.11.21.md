## 二、备份清单为什么是这三列

原来表头是「时间 / 大小」，第一列显示的是文件名（`fn-fail2ban-manual-20261111-162838.tar.gz`）。
真正想知道的只有一件事：**哪一份最新**。而文件名里那一串时间戳彼此长得几乎一样，
一次要点开三四个才分得出来。

现在把时间戳抽出来单独成列、按时间倒序，最新的永远在第一行；文件名退到悬停提示里，
需要辨认原始归档时仍看得到。

## 三、新增「恢复」

每行一个「恢复」按钮。这是这一版唯一的**写操作增量**，实现上有三条约束：

1. **先校验后写盘**。整份归档先读进内存：成员路径越界（绝对路径、含 `..`）、
   `manifest.app` 不是本应用、JSON 解析失败，全部在任何写操作之前返回。
   不会出现「检查到一半发现不对，配置已经改掉一半」。
2. **覆盖前自动留快照**。写托管配置之前先经 `jailconf.backup_file()` 复制一份到
   `var/backup/`，误恢复了还能翻回上一份。
3. **重载失败不当作恢复失败**。配置已经写进磁盘，界面单独提示「已恢复但 fail2ban 未重载」，
   用户自己点一次「重载配置」即可；把这种情形当成整体失败会让人以为恢复没生效而去重试。

恢复只认白名单成员：`manifest.json`、`prefs.json`、`notifications.json`、
`jail.d/<单文件>`、`filter.d/<名字>.local`。全程不用 `extractall()`，
目录 / 符号链接 / 设备成员一律忽略。

顺带修掉一个真实隐患：`list_backups()` 原来只按 mtime 排序，同一秒生成多个归档时
顺序取决于目录遍历，`prune()` 会把刚生成的那个当最旧的删掉。现在按 `(mtime, name)` 排序。
