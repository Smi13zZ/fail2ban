## 二、两个表原先差在哪

改之前这两张表列的是同一批字段，但各写一份渲染，已经走散了：

| | 概览（改前） | Jail 管理（改前） |
| --- | --- | --- |
| 接管 / 启用 | 两枚徽章挤在名称下面 | 拆成两个独立列 |
| 表头 | 「状态」 | 「运行状态」 |
| 红绿灯列 | 一列文字「运行中」 | 一列徽章「● 运行中」 |
| 封禁时长 | 有 | 有（但另一侧没有 maxretry/findtime） |

两边说的其实是同一件事，样子却不一样。现在抽出一个共用函数，两个页面都调它：

- 列一致：名称 / 接管 / 启用 / 运行状态 / maxretry / findtime / bantime /
  当前封禁 / 累计封禁 / 失败次数 / 操作，共 11 列；
- 徽章一致：三种状态各自一列；
- 对齐一致：名称左对齐，其余居中；
- 只有右侧按钮不同 —— 概览页列的是正在防守的 Jail，给「配置 / 封禁」；
  Jail 管理页给「配置 / 日志 / 启动(停止)」。

共用一份模板的意义不在省了多少代码，而在于后续不会再各自漂移。
顺带删掉三处因此失效的样式（名称 + 徽章上下两行、状态列、封禁时长列）。

## 三、GitHub 为什么没发

查明的原因：本地仓库提交与 tag 都停在 **v26.11.19**，
26.11.20 到 26.11.23 四个版本只在本地打了包，没有 commit、没有 push、没有打 tag。
CI（`.github/workflows/build-fpk.yml`）只认 `v*` 标签触发，
所以这四个版本在 GitHub 上根本不存在。

本轮已补：

- 提交 26.11.20–26.11.24 的全部改动与交付说明、验收截图；
- 打 tag 并推送，由 CI 构建并发布 Release。

发布后按惯例自检：下载 Release 里的 fpk 校验版本号 / 可执行位 / 九档图标，
并确认面板能读回新版本。
