# Fail2ban 26.11.28 交付说明

封禁管理页的两条工具栏合成一条，桌面每个宽度都排在一行里。

## 一、按需求逐条对照

| # | 要求 | 落地情况 |
| --- | --- | --- |
| 1 | 把（封禁管理页的控件）也调整成一行 | 原来的两条工具栏合成一条，八个控件从左到右排开 |
| 2 | 每个宽度都做成一行 | 21 个宽度逐一实测，桌面档全部一行、无横向溢出；390px 手机档三段式 |

## 二、原先为什么分两条

第一条是「Jail 选择器 / 手动封禁输入 / 封禁 / 解封全部」，
第二条是「搜索 IP / 共 N 项 / 排序字段 / 升降序」。

两条各自只占半行，因此翻页时找搜索框要往下看、找封禁要往上看，视线来回跳；
而且第二条工具栏本身还占一行高度，列表可视区被挤掉一截。

## 三、合成后的顺序

    Jail 选择器 | 手动封禁输入 | 封禁 | 搜索 | 共 N 项 | 排序字段 | 升降序 | 解封全部

「解封全部」是这一页唯一的破坏性操作，仍然推到最右并用淡红描边分开。

条数（共 N 项）现在由页面顶部统一计算：单 Jail 视图统计 `bannedIps` 里
命中搜索的条数，汇总视图统计 `entries` —— 两处取数方式不同，
所以抽了一个 `banCounts()` 出来，在渲染工具栏之前先算好。

## 四、为什么各宽度都能是一行

这一条上有八个控件，直观看是放不下的。两个关键点：

### 1. 输入框之间按比例分配空间

三个输入框都用 `flex: 1 1 auto` 配一组 `min-width: 0` + `max-width`
（220 / 260 / 200）：有余量时一起长到舒适宽度，窄了按同一比例一起收，
内容按省略号收尾。

它们原本不肯缩，是因为基类 `.toolbar input[type="text"]` 给了
`width: 260px`，以及默认的 `min-width: auto` —— 后者会把 flex 项的下限
卡在 input 的内在宽度上（约 166px），**与 `min-width` 无关**，
所以只写 `min-width: 120px` 完全不生效。

### 2. 两组各自允许收缩

左组（封禁相关）与右组（列表相关）都带 `min-width: 0`。
少了这一条，组的下限就是子控件下限之和，空间一紧就整组溢出、
把整页顶出横向滚动条 —— 这是本轮实际踩到的坑（960px 下 docSW 985）。

## 五、实测

在 1920 / 1440 / 1366 / 1280 / 1200 / 1100 / 1024 / 960 / 900 / 860 / 820 /
780 / 768 / 721 / 390 十五个宽度逐一量「工具栏行数 / 三个输入框宽度 / 是否横向溢出」：

| 内容区宽度 | 工具栏 | 三个输入框 | 横向溢出 |
| --- | --- | --- | --- |
| ≥ 896px | 一行 | 158 / 199 / 199 | 无 |
| 772px（1024 视口） | 一行 | 131 / 155 / 118 | 无 |
| 708px（960 视口） | 一行 | 119 / 136 / 84 | 无 |
| 697px（721 视口） | 一行 | 117 / 133 / 78 | 无 |
| 370px（手机 390） | 三段 | 整行 | 无 |

带真实封禁数据（3 个 IP）复测单 Jail 与「全部 Jail 汇总」两种视图：
四种宽度下工具栏均一行，选中条目后多出来的批量操作条（已选中 3 个 IP /
解封选中 / 取消选择）独立成行，不影响上面那条。
