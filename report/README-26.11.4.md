## 1. 图标换成你给的那张黑白盾牌

直接以你提供的 1024px 原图为母版，交给 LANCZOS 重采样出九档尺寸，不再手工描曲线 ——
手工重绘会和原图有偏差，而这张图本来就是要用的那一版。

小尺寸做了对比度收敛：40px 的盾牌边框降到 16px 后是一条灰雾，
因此 **≤48px 的档位额外走一遍对称对比曲线**（接近黑压到纯黑、接近白提到纯白），
让它在应用中心的小格子里仍然看得清是一个盾牌，而不是一团灰。

九档全套（16/24/48/64/72/96/128/256/512），外层另有 `ICON.PNG`(64) 与 `ICON_256.PNG`(256)。
面板内的标识和浏览器标签页图标同步换成同一套。

## 3. 表格列宽与排序

### 3.1 列错位

根因是 `table-layout: auto`：浏览器按内容分配列宽，同一列在不同行宽度不同。
「名称 + 徽章」这一列最典型 —— 名字长的行把徽章挤到第二行，名字短的行不挤，
于是有的行高两行、有的一行，看上去就是错位。

三处一起改：

| 改动 | 说明 |
| --- | --- |
| `table.fixed` + 每列 `width` | 按语义给每列一个够用的最小宽度，表头与单元格从此永远对齐 |
| 名称与徽章固定上下两行 | 不管名字多长、哪种语言，每行高度都一致 |
| 表格内按钮收紧内边距 | 英文 `Configure` 比中文「配置」宽，原内边距会被截断 |

概览表 8 列、Jail 表 11 列、封禁表 5～7 列，各自单独定宽；
Jail 表列多，宽度之和控制在 1440px 视口内，不需要横向滚动。

### 3.2 排序从表头挪到独立控件

表头点击取消，改为列表标题右侧的「字段下拉 + 升降序按钮」：

- 下拉里是该表的可排序字段（概览 / Jail：名称、当前封禁、累计封禁、失败次数；封禁：IP、到期时间）
- 按钮在升序 / 降序之间切换，图标跟着变（↑ / ↓）
- 换字段时给一个合理初值：文本列升序、计数列降序

三个列表各自记忆自己的排序状态。

## 开发中修掉的三个缺陷

**1. 封禁列表卡片丢了容器开标签（我在 26.11.3 引入的）**

`renderBanList` 里本该输出 `<div class="card"><h3>当前封禁列表（…）</h3>`，
做 i18n 改写时误把 `<div class="card"><h3>` 前缀一起删了，只剩孤立的 `</h3>`。
浏览器把标题文字当正文渲染，卡片样式整块塌掉。已修复并核对两处（单 Jail 与汇总视图）。

**2. 多个封禁 IP 被当成一个（功能缺陷，非本次改动引入）**

`f2b.py` 解析 `fail2ban-client status` 时统一按逗号切分，但封禁 IP 那一行是**空格分隔**的：

```
|  `- Banned IP list:	203.0.113.7 198.51.100.23 192.0.2.99
```

结果三行 IP 被合成一条，界面上显示成一串、点解封也会把整串当参数发出去。
改为按「空白或逗号」切 IP、文件列表仍按逗号切。实测三个 IP 恢复成三条独立记录。

**3. 英文残留扫描的临时文件被打进安装包**

早前做英文扫描留下的 `_missed.json` 等四个文件放在 `app/` 根目录，
打包过滤规则只按扩展名筛，于是跟着进了 `app.tgz`。已删除，并在
`build_fpk.py` 里加了出货前检查：发现 `_` 开头的文件或 `.pyc/.log` 直接中止构建。
