# Fail2ban 26.11.27 交付说明

日志页工具栏锁成一行，放不下时先压窄关键字框，不再让末尾两个按钮掉到第二行。

## 一、问题

26.11.26 把关键字、行数、导出搬到顶部后，这一条工具栏是默认换行的。
窗口一窄，最先掉到第二行的是末尾的「刷新 / 自动刷新」：

- 它们与上面那排控件不对齐，看着像多了一行零碎东西；
- 工具栏白占两行高度，日志可视区被挤掉一截。

在 1280 宽度下就会复现（内容区约 1028px，而控件总宽约 1100px）。

## 二、改法

桌面宽度下这一条不再换行，六个级别标签与五个控件始终并排。
一行放不下时按下面的顺序让步：

1. **关键字框先收窄**：200px → 120px，占位符超出部分按省略号收尾。
   它只是提示，压窄不影响可用性。
2. **行数与三个按钮不退让**：它们才是要点。
3. **级别筛选按内容占宽，不压窄**：压窄就得在筛选条内部横向滚动，
   六个级别被切成两截，比换行更难用。

右侧五个控件包在 `.log-tools` 里成组排布，整体靠右（`margin-left: auto`），
这样即使将来真的需要换行，也是这一组整体下移，不会出现「前三个在上面、
后两个在下面」的错位。

## 三、省出来的空间

控件密度比别处高一点，四处合计约 45px：

| 位置 | 改前 | 改后 |
| --- | --- | --- |
| 级别标签横向内边距 | 12px | 10px |
| 行内按钮横向内边距 | 12px | 8px |
| 控件间距 | 8px | 6px |
| 级别筛选容器内边距 | 4px | 3px |

## 四、实测

用 CDP 在 1920 / 1440 / 1366 / 1280 / 1200 / 1100 / 1024 / 960 / 900 / 860 /
820 / 780 / 768 / 721 / 390 十五个宽度逐一量「工具栏高度 / 是否同排 / 是否横向溢出」：

| 内容区宽度 | 工具栏 | 关键字框 | 横向溢出 |
| --- | --- | --- | --- |
| ≥ 796px | 一行 | 200px | 无 |
| 772 ~ 756px | 一行 | 200 → 194px | 无 |
| 708px | 一行 | 146px | 无 |
| 697px | 一行 | 135px | 无 |
| 390px（手机） | 三行 | 整行 | 无 |

一行最少需要 682px（级别筛选 268 + 五个控件收到最窄 414），
侧栏展开的内容区最窄也有 697px，所以桌面宽度下始终是一行。
