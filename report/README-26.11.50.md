# Fail2ban 26.11.50 交付说明

防护策略页的两颗按钮排成一行；一键更新的各阶段对齐。

## 一、防护策略的按钮

手机端卡片底部默认是「主要按钮独占一整行、次要按钮排在它上面靠右」。
防护策略这一处只有「放弃修改 / 保存并重载」两颗，照那条走要占两行高度，
而且次要按钮孤零零挂在上面靠右 —— 先看到的正是最不该先点的那个。

新增 `.card-foot.foot-2`：两颗按钮均分一行。`flex-basis` 必须归零，
否则会按内容宽度排成一宽一窄。中英文都放得下（英文 Discard changes /
Save and reload 各约 118px），所以不像三按钮那档要按语言分。

### 实测

| 视口 | 两颗按钮位置 | 宽度 | 卡片底栏高度 |
| --- | --- | --- | --- |
| 390×844 中文 | 同一行 | 166 / 166（满宽 340px，扣 8px 间距） | 53px（原 91px） |
| 320×640 中文 | 同一行 | 均分满宽 | 53px |
| 390×844 英文 | 同一行 | 166 / 166 | 53px |
| 1440×900 桌面 | 同一行（未变） | 86 / 100 | 51px |

## 二、一键更新各阶段

对照另一条产品线的实现逐项核过，三处不一致，都改了：

### 1. installing 阶段的文案

原先映射到「正在安装新版本」。但后端走到这一步时，安装包已经下完并校验过、
安装脚本也已拉起（`installer.py` 里 `_set("installing", ..., "安装包已就绪，正在重启服务")`），
实际发生的是面板即将被替换。原文案会让人以为还有很长的下载或安装可看。

改成「安装包已就绪，正在重启服务…」。

### 2. 轮询间隔 1000ms → 400ms

安装包不到 1MB，千兆内网一秒内就下完。间隔太长只能抓到一两个中间值，
进度条看起来像直接跳到 100%。

### 3. 失败原因不只闪一次 toast

遮罩一关 toast 就没了，回头想看「刚才为什么失败」没处看。现在同时记进
`state.update.error`，更新页状态条下面留一行红字：下载失败、校验失败、
安装脚本没起来都能对上。发起新的升级时清空。

只覆盖真正的升级失败与超时；「首个请求没发出去」那条不进这行 ——
它不是升级失败，只是升级期间服务正在重启。

### 其余部分本来就一致

| 项 | 状态 |
| --- | --- |
| 遮罩固定宽度 + 最小高度（切阶段不跳） | 一致 |
| 进度区两种形态共用固定高度（6px 条 + 7px 间距 + 17px 文字行） | 一致 |
| 百分比只增不减 | 一致 |
| 下载 100% 后切安装阶段仍保留满格 | 一致 |
| 轮询失败容忍 180 次再判超时 | 一致 |
| 装完自动重载页面 | 一致 |
| 失败后给「立即重新加载」入口 | 本产品有，更完整 |

### 实测

遮罩两个阶段截图核对：下载阶段（进度条 64% + 2.1 MB / 3.3 MB + 百分比）、
安装阶段（「安装包已就绪，正在重启服务…」+「准备中…」，无百分比）。
两阶段弹窗高度都是 227px，切换时不跳。
