## 二、三颗按钮一行

卡片底部动作条在手机上的规则是「主要按钮独占一行、其余折行」，三颗等宽按钮
排下来第三颗被挤到第二行，如你截图所见。

这一处改成一行均分：

| 项 | 值 |
| --- | --- |
| 按钮宽度 | 各 109px（三颗等分） |
| 字号 | 12px（原 14px） |
| 间距 | 6px |
| 文字截断 | 无 |

### 英文为什么仍折行

英文标签最长的「Remove from knock blacklist」需要 137px，均分后只有 109px，
差了 28px；把字号压到 11.5px 仍不够，再小就会明显比周围文字小一号。

三个方案摆出来对比过：

- 统一均分 + 省略号：英文变成「Push all curr…」，要长按才能看全；
- 统一均分 + 字号压到 10px：放得下但手机上小得扎眼；
- **中文一行、英文维持折行**：两种语言都不截断、不变小。

按你选的第三个方案实现，用 `<html lang>` 当条件（`html:lang(zh)`），
切语言时自动切换排布。

## 三、顺带修掉一处译文闭合标签

截图里那句说明的末尾还印着一串 `</div>`：

    只开「由 fn-knock 执行封禁」、不开这里也可以：action 在封禁发生的那一刻即时调用敲门，不需要等巡检。</div>

原因是 `fnk.instantHelp2` 的两条译文末尾都挂着 `</div>`。调用处用了 `esc()`，
所以容器没被提前闭合——但 `esc()` 只是把 `<` 换成 `&lt;`，标签原样显示了出来。

这是 26.11.29 那道闸门漏掉的一半：它只管「带尾标签的词条被当行内片段拼接」，
管不到「被转义后原样输出」。

## 四、新增闸门

`tools/check_web.py` 新增 `check_escaped_markup()`：译文里含任何 HTML 标签、
又被 `esc(t(...))` 包着输出的，判 FAIL 并指出行号与词条。

用变异样本验证：把那条 `</div>` 加回去，立刻报

    FAIL app.js:4063: 'fnk.instantHelp2' 的译文含 HTML 标签却被 esc() 转义输出…

顺带给闸门加了 `F2B_I18N` 环境变量，字典也能指向副本做变异测试——
否则针对字典的检查永远读仓库那份，变异测试是假绿（26.11.29 踩过同样的坑）。
