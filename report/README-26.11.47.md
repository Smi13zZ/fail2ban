# Fail2ban 26.11.47 交付说明

键值清单里的状态文字统一配色：正常态绿字、未就绪态橙字。

## 一、为什么改

每个状态自己写了徽章颜色类，同一类信息散成三种样子 —— 有的绿、有的橙、有的灰，
还有几个干脆是纯黑正文。「无响应」和「未检测到」是同一类问题（连不上 / 找不到），
却一个是橙一个是灰；「未安装」在概览页是红、在 fn-knock 页是灰。

同一张卡里一半是彩字、一半是黑字，读者要靠位置去猜哪个才是状态。

## 二、现在的规则

| 语义 | 颜色 | 涉及词条 |
| --- | --- | --- |
| 正常 | 绿 | 运行中、已启用、已安装、可读、监听中、可读 |
| 未就绪 | 橙 | 未检测到、未找到、未安装、未加入、无响应、已停止、未启用 |
| 无从判断 | 灰 | 「—」这类占位 |
| 非状态信息 | 正文色 | 数字、路径、版本号 |

「开机自启」「巡检状态」原先直接输出纯文本，现在也走同一套徽章。
「巡检间隔」这种纯数字说明保持正文色不变。

## 三、两处顺带修的问题

1. **fn-knock 三行双层徽章**：「action 文件 / 敲门过滤器 / 敲门 Jail」在模板里
   又包了一层 `<span class="badge muted">`，而那些词条本身已自带徽章。
   套两层时外层的类把内层颜色压掉 —— 只改词条看不出任何变化，必须同时去掉外层。
2. **排序下拉框继承粗体**：它嵌在卡片标题（`h3`，font-weight 600）里，
   `font-weight` 是可继承属性，不显式声明就会被标题带成 600。
   与页面上其余下拉框放在一起时明显粗一号。显式改回 400、字号 13px。

## 四、没动的地方

**Jail 管理与概览表格里的「接管 / 启用 / 运行状态」三列保持原样**
（绿字 + 浅绿底）。那是表格里的列状态，与键值清单是两套版式，混一起反而乱。
