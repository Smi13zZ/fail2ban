# Fail2ban 26.11.58 交付说明

危险操作的确认框全部换成站内模态，不再出现浏览器原生对话框。

## 一、问题

此前只有「一键升级」用的是站内模态，其余 **13 处** 仍在用 `window.confirm`：

| 位置 | 动作 |
| --- | --- |
| 概览 | 一键安装 fail2ban |
| Jail 管理 | 移除接管 |
| 封禁管理 | 解封该 Jail 全部、解封多 Jail 中的该 IP、解封选中、解封全部 Jail |
| 通知设置 | 删除渠道 |
| 过滤器 | 删除自定义过滤器 |
| 维护 | 删除备份、恢复备份 |
| 存储 | 清理日志、清理旧备份、全部清理 |
| fn-knock | 从黑名单移除单个 IP |

两个后果：

1. **视觉断层** —— 原生弹窗是浏览器的灰底系统框，按钮是系统的「取消 / 确定」，
   与面板里的按钮完全不是一个东西。
2. **同步阻塞** —— 弹窗期间渲染进程停住，升级遮罩里的进度轮询也跟着停。

当初只改了升级那一处，理由是「其余 13 处都是 `if (!confirm(...)) return;` 的守卫
写法，改成异步要把 14 个函数体各包一层回调，改动面大」。结果就是同一次会话里
两种弹窗交替出现 —— 这个判断是错的，该一次改完。

## 二、改法

`confirmDanger(message, opts)` 从「同步返回 boolean」改成「返回 Promise<boolean>」，
内部走站内模态；13 个调用点逐个改成 `.then(function (yes) { if (!yes) return; ... })`。

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 弹窗 | 浏览器原生 confirm | 站内模态（与升级确认同一个） |
| 标题 | 无（只有正文） | 按动作命名：删除 / 解封 / 清理日志 / 全部清理… |
| 主按钮 | 系统「确定」 | 与标题同名，危险操作用红色 |
| 正文换行 | 折成一段 | 带换行时按行显示 |
| Esc | 关抽屉 | 只关最上层（确认框优先） |

设置里那个「危险操作二次确认」开关语义不变：关掉后 `confirmDanger` 直接
`resolve(true)`，不弹窗。

## 三、实测（真机 fnos-test）

注入了 `window.confirm / alert / prompt` 的计数桩，逐个点开确认入口：

| 入口 | 标题 | 主按钮 | 原生弹窗 |
| --- | --- | --- | --- |
| 清理日志 | 清理日志 | 清理日志（红） | 0 |
| 清理旧备份 | 清理旧备份 | 清理旧备份（红） | 0 |
| 全部清理 | 全部清理 | 全部清理（红） | 0 |
| 删除备份 | 删除 | 删除（红） | 0 |
| 删除通知渠道 | 删除 | 删除（红） | 0 |

行为验证：

- 点「取消」→ 遮罩关闭，日志大小 58.7 KB 不变（确实没执行）；
- 点遮罩空白处 → 不误确认，弹窗仍开着；
- 按 Esc → 只关确认框，下面的抽屉不受影响。

全库扫描 `window.confirm / alert / prompt` 与裸 `confirm( / alert( / prompt(`：
剩余命中全部是注释里说明「为什么不用它」。

## 四、剩下的浏览器原生界面

还有两处是浏览器 API 本身提供的，改不了也不需要改：

- 浏览器通知授权（`Notification.requestPermission`）—— 系统级权限弹窗，任何网页都一样；
- 文件下载（备份 / 日志导出）—— 浏览器自己的下载行为。

其余交互（下拉框、日期、选择条）本来就都是站内实现。
